網址內容

https://poterpan.github.io/lala-food-feed/meta.json這一版的產生時間、各檔案筆數、因條件不足沒收錄的店家數與原因
https://poterpan.github.io/lala-food-feed/lala/extra.json與 lala-food 的 extra.json 同格式：visited_from_wish、visited_add相容
https://poterpan.github.io/lala-food-feed/lala/notes.json與 lala-food 的 notes.json 同格式：必點品項 items、拉拉熊原話心得 comment相容
https://poterpan.github.io/lala-food-feed/lala/posts.json與 lala-food 的 posts.js 同內容（純 JSON）：每家店（CID）對應的拉拉熊貼文相容
https://poterpan.github.io/lala-food-feed/lala/data.jslala-food 目前公開的 data.js，已套用上面三個檔案，可直接替換相容
https://poterpan.github.io/lala-food-feed/lala/posts.jslala-food 目前公開的 posts.js，已併入找到的貼文，可直接替換相容

venues.json 欄位

JSON 陣列，一家店一筆：

欄位說明
cidGoogle 地點 CID（與 lala-food 同一套 ID）
place_idGoogle Places place_id（只從收藏清單對到的店為 null）
name / addr / city / lat / lng店名、地址、縣市、座標
names_in_threadsThreads 上出現過的寫法與次數，例如 {"烏弄": 10, "乌弄": 5}
stance誰說了什麼：author:* 是拉拉熊本人，other_user:* 是網友；recommend / negative / mixed / question / mention
experience拉拉熊吃過沒：visited / planned / not_yet / unknown
author_recommends拉拉熊本人的推薦是否多於負評
in_lala_visited / in_lala_wish是否已在 lala-food 的已去過／愛心清單
first_seen / last_seen在 Threads 上第一次、最後一次被提到的時間
sources所有提到這家店的 Threads 原文連結

brands.json 欄位

JSON 陣列，一個品牌一筆。分店不確定的連鎖店推薦放這裡，不放進 venues.json：

欄位說明
brand品牌名稱
names_in_threads / stance / experience / author_recommends同 venues.json
items / comment必點品項、拉拉熊原話心得（逐字、已對照原文）
saved_branch_cids拉拉熊收藏清單裡這個品牌的分店 CID
lala_branch_cidslala-food 現有資料裡這個品牌的分店 CID，可用來把品牌推薦掛到地圖上的分店
mentions / first_seen / last_seen / sources提及次數、時間範圍、Threads 原文連結

資料怎麼來的

每次更新會抓拉拉熊的新貼文與回覆，用 LLM 從文字、照片、留言裡的「這是哪家？」問答認出店家，再對應到 Google 地圖的店家（CID）。只收錄有把握的結果： 名字不一致的、連鎖店沒有分店證據的、泛稱（例如「鐵板炒飯」）都不會出現在這裡。這一版因此沒收錄的：連鎖店無分店證據 6 家、店名對不上 46 家、只有待審核的提及 23 家、泛稱或地名 6 家。

每一筆都附 Threads 原文連結，可以逐筆檢查。

接到 lala-food

在 update.mjs 先讀 lala/extra.json、lala/notes.json，讀不到就用本機原本的檔案；本機的手動設定（例如 visited_remove）永遠優先。 也可以直接讀 venues.json，用 experience 與 author_recommends 決定放「已去過」或「愛心」。
