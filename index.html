v1/venues.json 主要欄位

欄位說明
id店家 ID：Google 地點 CID（與 lala-food 同一套）；中國大陸的店用高德，為 amap:<高德 POI ID>
cidGoogle 地點 CID；中國大陸（高德）的店為 null，lala/ 相容檔案不收這些店
place_idGoogle Places place_id；只來自收藏清單的店、高德的店為 null
amap_id高德 POI ID（中國大陸的店），其餘為 null
maps_url開啟地圖的連結：Google 地圖，或中國大陸的店用高德（手機會開高德 App）
name / address / city / lat / lng / category店名、地址、縣市、座標、分類
brand所屬連鎖品牌（不是連鎖則為 null）
author.visited拉拉熊說過或照片顯示他吃過
author.recommends拉拉熊本人的推薦多於負評為 true，相反為 false，沒表態為 null
author.saved / saved_at / saved_note是否在拉拉熊分享的任一 Google 地圖清單、加入時間（Unix 秒）、他在清單上的備註
author.lists在哪幾份清單：id、title、meaning（saved＝收藏；recommended＝他說平常會去吃，算吃過且推薦）
basis依據：threads（Threads 上有提到）、saved_list（在收藏清單）
tier分級：author_visited 拉拉熊吃過 › author_endorsed 拉拉熊推薦 › community_recommended 網友推薦（推薦多於差評）› author_saved 只在他的清單 › mentioned 只被提到
community網友推薦：推薦次數、推薦人數（不同網友，不公開帳號）、拉拉熊的反應（visited/planned/not_yet/unknown）、是否他自己發問、網友推薦的品項、差評次數（negative）。拉拉熊沒提過、只有網友差評的店不收錄
names_in_threadsThreads 上出現過的寫法與次數
stance誰說了什麼：author:* 是拉拉熊，other_user:* 是網友
items / quotes必點品項、拉拉熊原話（逐字、已對照原文，附連結）
post_urls拉拉熊正式介紹這家店的貼文（lala/posts.js 另外也收他自己提到這家店的回覆）
related_post_urls所有跟這家店有關的拉拉熊貼文／回覆，包含只有網友在他串底下提到的情況
first_seen / last_seen / sourcesThreads 上第一次與最後一次提到的時間、所有原文連結

資料怎麼來的

每次更新會抓拉拉熊的新貼文與回覆，用 LLM 從文字、照片、留言裡的「這是哪家？」問答認出店家，再對應到 Google 地圖的店家（CID）。 Threads 上的店只收錄有把握的結果；這一版因條件不足沒收錄的：店名對不上 103 家、只有待審核的提及 23 家、連鎖店無分店證據 1 家、泛稱或地名 5 家、只有網友差評 7 家。收藏清單直接來自拉拉熊本人分享的 Google 地圖清單。

每一筆 Threads 證據都附原文連結，可以逐筆檢查。GitHub repo
